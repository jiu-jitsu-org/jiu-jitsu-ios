## 환경 제약 (먼저 밝혀 둠)

- 로컬 시크릿이 가짜(dummy)다. 실제 서버·소셜 로그인·웹 화면은 띄울 수 없다.
- 그래서 QA는 세 갈래로 한다.
  1. **코드 적대적 점검** — 각 기능의 Reducer·View·Bridge를 사용자 시나리오대로 따라가며 깨지는 경로를 찾는다.
  2. **시뮬레이터 화면 점검** — 로컬 전용 캡처 하네스(커밋 안 함)로 TCA preview 의존성을 붙여 화면을 띄우고 기기 크기·큰 글씨별로 찍는다.
  3. **빌드·출시 준비 점검** — Debug·Beta·Release 빌드, Info.plist·권한 문구·엔타이틀먼트·Xcode Cloud 스크립트.
- 실기기 점검과 TestFlight 업로드는 사람 손이 필요하다. 체크리스트로 넘긴다.

## 진행 단계

1. 계획 (이 문서)
2. 점검 — A1~A7 코드 점검 + R 화면 점검을 병렬로 (최대 8명)
3. 검증 — 나온 결함을 코드로 직접 다시 확인, 오탐 제거
4. 수정 — 화면 모양이 바뀌지 않는 **기능 결함만** 고친다. 화면·문구 디자인이 바뀌는 건 논의 거리로 남긴다 (팀 규칙: UI 변경은 논의 먼저)
5. 빌드 확인 → 적대적 리뷰 → 커밋·푸시
6. 보고서 (이 폴더의 REPORT.md + 시각화 페이지)
