# A3 대회 기록 + 관장 인증 점검 결과

기준: `qa/ios-release-qa` @ b1b40b6. 경로는 모두 `JiuJitsuConnect/Targets/` 아래. (`Presentation/Sources/` 는 `P/` 로 줄임)

## 점검한 흐름

대회 기록 — MY에서 추가
- 결과 → 대회명 → 연도 → 부문 → 저장 → 완료 화면: OK. 저장 결과를 받은 뒤에만 완료 화면으로 넘어감(`saveFinished`).
- 단계마다 뒤로가기: OK. 단계만 한 칸 뒤로 가고 입력값은 그대로 남음. 중간 단계에서는 시스템 스와이프도 막혀 한 단계씩 뒤로 감(#390, `blocksSwipeBack`).
- 머리줄 '취소'(어느 단계든): 확인 없이 흐름 전체를 닫고 입력을 버림. 주석에 적힌 의도된 동작이라 결함으로 보지 않음(`CompetitionInfoFeature.swift:482-485`).
- 저장 연타·저장 중 뒤로가기·스와이프: OK. `isSaving` 확인 + 화면 전체 `.disabled` + 스와이프 막기 + 단계가 바뀌는 동안 누름 막기(`allowsHitTesting(shownStep == store.step)`)로 기록이 두 번 저장되지 않음.
- 저장 실패: OK. 입력값을 유지하고 입력 화면 안에 토스트를 띄워 같은 자리에서 다시 저장할 수 있음.
- 완료 화면 '부문 추가' → 메달 → 부문 → 저장, 그 뒤 뒤로가기로 완료 화면 복귀: OK.
- MY 목록 '부문 추가'(이미 있는 대회에 부문 더하기): OK.
- 대회명 공백만: OK. 다음 버튼이 꺼지고 키보드 Return도 막힘. 붙여넣은 줄바꿈은 지움. 앞뒤 공백은 저장할 때 DTO가 잘라냄.
- 대회명 이모지·최대 길이: 앱에는 길이 제한이 없음. 서버 한도를 넘으면 원인을 알 수 없는 "저장하지 못했어요"만 반복될 수 있음 → 서버 확인 항목으로 넘김.
- 자동완성: 디바운스·취소, 고른 뒤 이름이나 연도를 고치면 연결 해제, 실패하면 직접 입력: OK.
- 날짜 경계: 연도만 받으므로 윤년·월말은 해당 없음. 휠은 올해부터 1990년까지(미래 연도 없음). 수정할 기록의 연도가 범위 밖이면 목록에 그 연도를 더함: OK.
- 체급 입력(붙여넣기 1000, 쉼표, ".5"): OK.

대회 기록 — 수정·삭제
- 수정 화면에 기존 값 채우기(메달·이름·연도·도복·띠·체급·무제한(옛 '+kg')·앱솔루트·연결 대회): OK. 수정 화면에는 '건너뛰기'가 없어 기존 부문이 지워지지 않음.
- 수정 저장 연타: OK. 첫 번째 누름에서 화면이 닫혀 두 번째 누름은 갈 곳이 없음.
- 수정 저장 실패: **문제** → A3-2
- 수정 화면 머리줄 '삭제': 확인 알럿 있음. [삭제] 연타 막힘. 알럿이 떠 있는 동안 스와이프 막힘: OK.
- MY 목록 시트 '삭제'(그 대회의 부문 전부): 확인 알럿 있음. 부문이 여럿이면 몇 개가 함께 지워지는지 알림: OK.
- 삭제 실패 복구: 먼저 화면에서 지우지 않으므로 목록이 그대로 남음(OK). 다만 안내 문구가 맞지 않음 → A3-3
- 고정·순서 바꾸기 저장 중 막기(`isLoadingProfile`): OK.
- 다른 MY 화면이나 다른 곳에서 바꾼 기록과 겹칠 때: **문제(데이터 유실)** → A3-1, A3-7

대회 기록 — 웹 '내 기록에 남기기'(#250, #304, #397)
- payload 검사: 이름이 없거나 공백만, 연도가 없음·문자열·Bool·소수·범위 밖·아주 큰 수 → nil로 처리하고 로그만 남김, 크래시 없음. competitionId가 음수·소수·문자열이어도 연결 없이 엶: OK.
- 연타·중복 전달로 입력 화면이 두 번 쌓이는지(대회 탭·홈·홈 모달 안): OK. 맨 위가 이미 기록 추가 화면이면 쌓지 않음.
- 비로그인 → 로그인 모달 → 로그인 후 그 탭에 이어서 열기, 로그인 취소·가입 포기·세션 만료 알럿 닫기에서 대기 중 기록 버리기: OK.
- 저장 직전에 프로필을 새로 받아 그 위에 더하기: OK.
- 저장 성공 → 홈·대회·MY 웹뷰 모두에 COMPETITION_RECORD_SAVED 보냄: OK. 실패하면 보내지 않음: OK. 저장 중 로그아웃했으면 보내지 않음: OK. 입력 화면이 닫혀도 알림은 감: OK.
- MY에서 직접 추가·수정·삭제했을 때 웹에 알리는지: **알리지 않음** → A3-4
- MY 스택에 쌓인 웹(커뮤니티 활동 → 글 → …)에서 연 대회 상세: **기록 추가를 받지 않음** → A3-9

관장 사범 인증(#388, #389)
- 시트 단계: 처음 / 사진 고른 뒤 / 심사 중(사진 바꾸기) / 반려 / 승인(문의 메일, 메일 앱이 없으면 주소 복사): OK.
- 역할이 OWNER인데 신청 기록이 없으면 승인으로 봄: OK.
- 신청 연타: OK. 시트가 바로 닫히고, 올리는 동안 덮개로 화면을 막고, 메뉴 다시 열기도 막음.
- 심사 중 다시 신청: '사진 바꾸기'로 서류만 바꿀 수 있음(설계대로).
- 반려 사유 표시: 있음. 다만 두 줄을 넘으면 잘림 → A3-6
- 업로드 실패, 인증 요청 실패: OK. 덮개를 풀고 토스트를 띄움.
- 사진 고른 뒤 시트 내리기: 고른 사진을 버림(의도된 동작).
- 앨범 권한 거부: PHPicker라 권한 없이도 열림(OK). 카메라 권한 거부: 안내 없음 → A3-8
- 사용자 프로필을 아직 못 받았거나 받지 못했을 때 시트 상태: **문제** → A3-10

## 결함

### A3-1 [P0] 홈에 쌓인 내 MY에서 대회를 저장하면 그사이 다른 곳에서 추가한 대회 기록이 서버에서 지워짐
- 페르소나: P4 검은띠 관장(기록이 여러 개), P2 급한 손(탭을 빠르게 오감)
- 재현:
  1) 홈 탭에서 피드나 글의 내 닉네임을 눌러 커뮤니티 스택에 내 MY를 연다. 이때 프로필(P0)을 받는다.
  2) 하단 **MY 탭**으로 가서 대회 A를 추가·저장한다. 또는 대회 탭의 상세 → '내 기록에 남기기'로 A를 저장한다.
  3) **홈 탭**으로 돌아간다. 쌓인 MY가 그대로 보이고 A가 없다(다시 불러오지 않음).
  4) 그 MY에서 대회 B를 추가한다. 고정, 순서 바꾸기, 수정, 삭제도 마찬가지다.
  5) 서버에는 P0 + B만 저장되어 **A가 사라진다**.
- 기대 / 실제: 다른 곳에서 남긴 기록을 지키며 더해야 한다. / MY는 들고 있던 프로필의 대회 목록을 통째로 다시 보낸다(대회 저장은 목록 전체 교체). 쌓인 MY의 프로필은 탭을 옮겨 다녀도 새로 받지 않는다.
- 근거:
  - `P/Features/MyProfile/MyProfileFeature.swift:983-993`: 추가는 `state.communityProfile`(캐시)에 `addingCompetition`. 수정 `:1010-1020`, 삭제 `:1035-1040`·`:1657-1664`, 고정 `:1089`, 순서 `:1118`도 같은 캐시를 씀.
  - `Data/Sources/Network/DTO/Request/PostCommunityProfileRequestDTO.swift:47-49`: "대회 저장은 목록 전체 교체".
  - `P/Features/MyProfile/MyProfileFeature.swift:340-347`: 쌓인 MY는 `onAppear` 때만 다시 받음. 그런데 `P/Features/AppTab/AppTabView.swift:352-360`의 탭은 opacity로만 감추고 뷰를 유지하므로, 탭을 옮겨 돌아와도 `onAppear`가 다시 오지 않음(같은 파일 주석 "탭은 뷰를 유지해 onDisappear가 오지 않는다").
  - `P/Features/AppTab/AppTabFeature.swift:627-631`: 웹 경로로 저장하면 `state.myPage`(탭 MY)만 고치고, 홈에 쌓인 MY는 그대로 둠.
  - `P/Features/AppTab/AppTabFeature.swift:248-253`: 앱 복귀 때 다시 받는 것도 MY 탭을 보고 있을 때만.
  - `P/Features/Community/CommunityFeature.swift:611-614`: `.session(.profileUpdated)`는 웹뷰에만 전하고 쌓인 MY에는 전하지 않음.
  - 반대 방향도 위험함: 쌓인 MY에서 저장하면 `competitionAdded` 등이 부모에 아무것도 알리지 않음(`MyProfileFeature.swift:1051-1071`). 그래서 탭 MY는 탭에 들어갈 때 다시 받기(`:357-365`)에만 기댐. 이 다시 받기는 실패해도 조용히 넘어가므로(`:387-390`) 불안정한 망(P3)에서는 같은 유실이 생김.
  - 웹 경로는 이 위험을 알고 저장 직전에 새로 받음(`AppTabFeature+CompetitionRecord.swift:66-82` 주석: "그 사이 다른 곳에서 남긴 기록이 지워지지 않게"). MY 경로에는 이 처리가 없음.
- 고치는 방향: MY의 대회 저장(추가·수정·삭제·고정·순서)도 저장 직전에 `fetchProfile`로 새로 받아 그 위에 바꾼다. 또는 대회 저장 성공을 모든 MY 인스턴스(탭 MY, 홈 스택·모달 안의 MY)에 반영한다. · 분류: 코드수정-화면변화없음
- 확신도: 중간. 코드 경로는 확실함. "탭을 옮겨도 쌓인 MY의 onAppear가 다시 오지 않음"은 실기기에서 한 번 확인 필요. 대회 외 섹션(도장명 등)도 같은 캐시를 보내는지는 A2 묶음에서 확인 권장.

### A3-2 [P2] 대회 기록 수정 저장이 실패하면 고친 값이 모두 사라짐
- 페르소나: P3 지하철
- 재현: 1) MY → 대회 줄 → 부문 수정 2) 대회명·연도·체급 등을 고치고 '완료' 3) 네트워크 실패
- 기대 / 실제: 추가 흐름처럼 입력 화면에 남아 다시 저장할 수 있어야 한다. / 저장을 보내기 전에 화면부터 닫아(`destination = nil`), 실패하면 MY에 "저장하지 못했어요. 다시 시도해 주세요" 토스트만 뜬다. 고친 값은 버려져 처음부터 다시 입력해야 한다.
- 근거: `P/Features/MyProfile/MyProfileFeature.swift:1020-1022`(저장 전에 닫음), `:837-851`(실패하면 MY 토스트). 추가 흐름은 `:1061-1066` → `CompetitionInfoFeature.swift:447-450`에서 입력값을 유지함. 커밋 0554c00 "수정 모드는 기존처럼 저장 후 바로 닫음"은 성공 경로만 다룸.
- 고치는 방향: 수정도 추가처럼 저장 중에는 화면을 두고(`isSaving`), 성공하면 닫고, 실패하면 화면 안 토스트로 알린다. · 분류: UI논의필요(저장하는 동안 화면에 머무는 방식이 바뀜)
- 확신도: 높음

### A3-3 [P3] 대회 기록 삭제가 실패해도 "저장하지 못했어요"라고 안내함
- 페르소나: P3 지하철

- 기대 / 실제: "삭제하지 못했어요. 다시 시도해 주세요"라고 알려야 한다. / 공통 실패 처리를 타서 "저장하지 못했어요. 다시 시도해 주세요"가 뜬다. 기록을 못 찾은 경우에는 이미 "삭제하지 못했어요"를 씀(`:1667`). 그래서 문구가 둘로 갈림.

- 고치는 방향: 삭제 실패에 전용 실패 액션이나 문구를 둔다. · 분류: UI논의필요(문구)
- 확신도: 높음

### A3-4 [P3] MY에서 대회를 추가·수정·삭제해도 열린 웹에 알리지 않음 → 대회 탭의 '결과 남기기' 배너가 남아 같은 기록을 또 남길 수 있음
- 페르소나: P4
- 재현: 1) 대회 탭에서 끝난 관심 대회의 '결과 남기기' 배너가 보이는 상태 2) MY 탭 → 대회 추가 → 자동완성에서 그 대회를 골라 저장 3) 대회 탭으로 돌아감
- 기대 / 실제: 웹 경로로 저장했을 때처럼 배너가 닫혀야 한다. / MY 경로는 COMPETITION_RECORD_SAVED도 PROFILE_UPDATED도 보내지 않는다. 배너가 남아 다시 누르면 같은 기록이 하나 더 생길 수 있다. 수정·삭제 뒤에도 웹 프로필이나 대회 화면은 새로 고칠 때까지 예전 기록을 보여 준다.
- 근거: `P/Features/MyProfile/MyProfileFeature.swift:1051-1081`(`competitionAdded/Updated/Deleted`에 `.delegate(.profileUpdated)` 없음). `P/Features/AppTab/AppTabFeature.swift:348-352`(웹 방송은 `profileUpdated` 위임일 때만). `AppTabFeature+CompetitionRecord.swift:96-105`(COMPETITION_RECORD_SAVED는 웹이 연 흐름에서만 보냄).
- 고치는 방향: MY 대회 저장이 성공하면 `profileUpdated`를 방송한다. 등록 대회에 연결된 추가면 그 id로 COMPETITION_RECORD_SAVED도 보낸다. · 분류: 웹/서버 확인필요(웹이 배너를 언제 다시 확인하는지)
- 확신도: 중간

### A3-5 [P3] 대회명 화면의 깜빡이는 커서가 반복 타이머를 해제하지 않아 계속 쌓임
- 페르소나: P5 극단 입력(지웠다 썼다 반복)
- 재현: 1) 대회명 단계에서 글자를 쳤다가 모두 지우기를 반복 2) 기록 추가 화면을 여러 번 열고 닫기
- 기대 / 실제: 커서 뷰가 사라지면 타이머도 멈춰야 한다. / 빈칸이 될 때마다 `BlinkingCursorView.onAppear`가 0.5초 반복 `Timer`를 새로 만들고 끄지 않는다. 앱이 끝날 때까지 타이머가 쌓여 0.5초마다 깨어난다(배터리·CPU).
- 근거: `P/Features/MyProfile/Competition/CompetitionNameView.swift:214-219`
- 고치는 방향: `TimelineView`나 `.task { while … try await Task.sleep }`로 바꾼다. 또는 `onDisappear`에서 `invalidate`한다. · 분류: 코드수정-화면변화없음
- 확신도: 높음

### A3-6 [P2] 관장 사범 인증 반려 사유가 두 줄을 넘으면 잘려 끝까지 읽을 수 없음
