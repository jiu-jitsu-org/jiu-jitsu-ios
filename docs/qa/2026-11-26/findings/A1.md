## 결함

### A1-01 [P1] 스플래시가 '연결 문제'가 아닌 서버 오류까지 "서버에 연결하지 못했어요"로 처리해, 다시 시도만 끝없이 반복된다
- 페르소나: P8 떠나는 사람(다른 기기에서 탈퇴 · 계정 정리), P3 지하철
- 재현: 1) 로그인한 채로 앱을 끈다 2) 서버가 이 기기의 refresh 요청에 세션 종료 4개 코드(A0002 · A0003 · A0009 · U0002)가 **아닌** 오류를 준다 — 예: 탈퇴 처리된 계정 U0004/U0005, 존재하지 않는 회원 U0011, 앱이 모르는 새 코드, 400/403/429 본문 없음, 200인데 응답 형식이 바뀜(`dataParsingFailed`) 3) 앱을 켠다
- 기대 / 실제: 기대 — #367 커밋 의도("망 없음 · 5xx · 시간 초과"일 때만 다시 시도를 묻고, 그 밖엔 로그인 화면)대로, 다시 시도해도 풀리지 않는 오류면 로그인 화면이나 둘러보기로 나갈 수 있어야 한다. 실제 — 모든 비-세션종료 오류가 연결 실패로 분류되고, 알럿 버튼은 [다시 시도] 하나뿐이라 같은 오류가 계속 나면 스플래시에서 영영 못 나간다(앱 삭제 말고 탈출구 없음).
- 근거:
  - `Presentation/Sources/Features/Splash/SplashFeature.swift:261-269` — `if case .apiError(code, _)? = error as? DomainError, code.endsSession { … } else { send(.autoLoginConnectionFailed) }` : 세션 종료 코드가 아니면 오류 종류와 상관없이 전부 연결 실패
  - `Domain/Sources/Entities/Error/APIErrorCode.swift:35-42` — `endsSession`은 4개 코드만 true. U0004 · U0005 · U0011 · unknown은 false
  - `Data/Sources/Network/NetworkError.swift:64-81` — 응답 형식 오류는 `.dataParsingFailed`, 모르는 코드는 `.serverError(code:…)`로 와서 위 else로 감
  - `Presentation/Sources/Features/Splash/SplashView.swift:27-35` — `secondaryButton: nil`
  - 의도 확인: `git show 2008c85` "자동 로그인이 망 없음 · 5xx · 시간 초과로 끝나면 … [다시 시도]. 세션 종료 코드일 때만 로그인 화면"
- 고치는 방향: 연결 실패로 볼 오류를 `networkUnavailable` · `timeout` · 5xx(`serverError` statusCode ≥ 500) · 시간 초과로 좁히고, 그 밖의 오류는 토큰을 지키되 로그인 화면(또는 둘러보기)으로 넘긴다. 또는 알럿에 두 번째 버튼(예: "로그인 화면으로")을 둔다(이건 UI논의). · 분류: 코드수정-화면변화없음(분류 좁히기) / UI논의필요(두 번째 버튼) / 웹/서버 확인필요(탈퇴 · 영구삭제 계정의 refresh 응답 코드)
- 확신도: 중간 (코드 경로는 확실, 실제로 서버가 어떤 코드를 주는지가 남음)

### A1-02 [P1] 상세를 전체 화면 모달(OPEN_SUBVIEW modal)로 띄운 상태에서 게스트가 로그인 필요 행동을 하면 로그인 안내 · 로그인 창이 모달 밑에 깔려 안 보인다
- 페르소나: P8 게스트로 둘러보기
- 재현: 1) 게스트로 홈 피드 진입 2) 웹이 `OPEN_SUBVIEW`(presentation: modal)로 글 상세를 띄움(`home.detailCover`) 3) 모달 안에서 좋아요 · 댓글 · 신고 등을 누름 → 웹이 `AUTH_LOGIN_PROMPT` 또는 `AUTH_LOGIN_MODAL` 전송
- 기대 / 실제: 기대 — 모달 위에 "로그인하고 좋아요를 눌러 보세요" 알럿 또는 로그인 창이 뜬다. 실제 — 로그인 안내 알럿은 탭 화면(AppTabView)의 overlay에만 붙어 있어 fullScreenCover 아래에 그려지고, 로그인 창(`loginCover`)은 같은 뷰에 붙은 두 번째 fullScreenCover라 이미 `detailCover`가 떠 있으면 SwiftUI가 띄우지 못한다. 사용자는 눌러도 아무 반응이 없고, 모달을 닫으면 그제서야 철 지난 로그인 안내가 피드 위에 뜬다. 웹은 대기 행위를 들고 응답을 기다린다.
- 근거:
  - `Presentation/Sources/Features/AppTab/AppTabView.swift:151-155` (`loginCover` fullScreenCover)와 `:158-196` (`detailCover` fullScreenCover)가 같은 뷰에 나란히 붙음
  - 같은 파일 `:177-195` — 모달 안에는 기기 알림 · 세션 만료 · 탈퇴 안내 · 토스트만 `isInCover`로 다시 그림. 로그인 안내는 `:197-203` 탭 화면에만 있음
  - `Presentation/Sources/Features/Community/CommunityFeature.swift:659-660, 791-794` — 모달 상세의 `loginPromptRequested` · `loginModalRequested`가 AppTab으로 올라감 → `AppTabFeature.swift:271-281`
  - 대조: 알림 권한 시트는 같은 이유로 모달이 떠 있으면 띄우지 않는다 — `AppTabFeature+NotificationPrompt.swift:42-47` "상세 모달이 떠 있으면 탭 화면에 붙인 시트가 모달 아래라 보이지 않는다"
- 고치는 방향: 로그인 안내 알럿도 세션 만료 알럿처럼 `isInCover` 바인딩으로 모달 안에 한 벌 더 그리고, 로그인 창은 모달이 떠 있으면 모달 안(NavigationStack 쪽)에서 띄우거나 모달을 닫고 띄운다. · 분류: 코드수정-화면변화없음 + 웹/서버 확인필요(웹이 modal을 실제로 쓰는 화면이 있는지)
- 확신도: 중간 (iOS 쪽 경로는 확실. 웹이 지금 modal을 쓰지 않으면 잠복 결함)

### A1-03 [P1] 스토어 앱 ID가 비어 있어 '업데이트가 필요해요' 안내의 [업데이트]가 아무것도 열지 않는다 — 꼭 필요한 업데이트가 걸리면 앱이 영구히 막힌다
- 페르소나: P1 처음이 (사실상 전원)
- 재현: 1) 서버 최소 버전을 지금 앱보다 높게 설정 2) 앱을 켬 → 닫을 수 없는 "업데이트가 필요해요" 3) [업데이트] 탭
- 기대 / 실제: 기대 — App Store의 앱 페이지가 열린다. 실제 — `storeURL()`이 nil이라 아무 일도 없고, 안내는 닫을 수 없어 앱을 쓸 방법이 없다. 권장 업데이트의 [업데이트]도 스토어를 열지 못하고 그냥 홈으로 간다.
- 근거:
  - `App/Sources/Composition/AppStoreLink.swift:10` — `static let appID: String? = nil` ("출시 전이라 아직 없다 — 정해지면 넣는다")
  - `Presentation/Sources/Features/App/AppFeature.swift:123-126` — `guard let storeURL = appVersionClient.storeURL() else { return .none }`
  - `Presentation/Sources/Features/App/AppView.swift:44-53` — 버튼 하나, `set: { _ in }`로 닫을 수 없음
- 고치는 방향: TestFlight 올리기 전에 App Store Connect의 Apple ID(숫자)를 `AppStoreLink.appID`에 넣는다. 서버 최소 버전은 appID가 들어간 빌드가 나간 뒤에만 올린다는 운영 규칙도 남긴다. · 분류: 사람이 실기기 확인(값 넣기 + 스토어 열림 확인)
- 확신도: 높음

### A1-04 [P2] 스플래시 동안 미리 불러 둔 홈 피드의 웹 프로세스가 이어받기 전에 죽으면, 홈이 끝나지 않는 스피너(또는 빈 흰 화면)로 남는다
- 페르소나: P3 지하철(느린 망으로 스플래시가 길어짐), P6 작은 기기(메모리 압박)
- 재현: 1) 로그인 상태, 저장된 access token이 아직 유효 → 스플래시가 홈 피드를 미리 불러오기 시작 2) 스플래시 중 홈으로 나가거나 메모리 압박으로 웹 콘텐츠 프로세스가 종료됨(문서를 다 받기 전) 3) 앱으로 돌아와 스플래시가 끝나고 홈이 그 웹뷰를 이어받음
- 기대 / 실제: 기대 — 홈 · 대회 목록 웹뷰처럼(#479) 다시 불러오거나 오류 화면(다시 시도)을 보인다. 실제 — 이어받기 전 대리자(`HomeFeedPreloadRecorder`)가 `webViewWebContentProcessDidTerminate`를 구현하지 않아 종료가 기록되지 않는다. 이어받은 홈은 `isLoading = true` 그대로라 로딩 덮개가 탭을 막은 채 영원히 돌고(당겨서 새로고침도 덮개에 막힘), 문서를 받은 뒤 죽었으면 덮개는 걷혀도 흰 화면이다. 앱을 다시 켜야 풀린다.
- 근거:
  - `Presentation/Sources/WebBridge/HomeFeedPreloader.swift:171-266` — 기록하는 이벤트는 started · finished · failed · message뿐, 프로세스 종료 콜백 없음
  - `Presentation/Sources/WebBridge/BridgeWebView.swift:232-236` — 이어받으면 `markLoaded` 후 다시 부르지 않음
  - `Presentation/Sources/WebBridge/BridgeWebView.swift:689-749` — 종료 복구는 코디네이터가 대리자일 때만 동작
  - `Presentation/Sources/Features/Community/CommunityFeature.swift:62` — `isLoading = true`로 시작, `WebLoadingOverlay`는 `allowsHitTesting(isLoading)`(`WebLoadingOverlay.swift:34`)
- 고치는 방향: Recorder에 `webViewWebContentProcessDidTerminate`를 넣어 `.terminated` 이벤트로 기록하고, `handOff` 재생 때 `coordinator.webViewWebContentProcessDidTerminate(webView)`를 불러 기존 #479 복구를 타게 한다. · 분류: 코드수정-화면변화없음
- 확신도: 중간 (경로는 확실, 발생 빈도는 낮음)

### A1-05 [P2] 푸시 · 공유 링크로 앱을 켰는데 그 사이 로그인이 만료됐으면, 만료 안내 없이 조용히 게스트가 된다
