## 결함

### A4-1 [P1] 마케팅(광고성) 정보 수신 동의·철회 때 처리 결과와 날짜를 알리지 않음
- 페르소나: P7 거절하는 사람, P8 떠나는 사람
- 재현: 1) 설정 › 알림 2) '마케팅 정보 알림'을 켜거나 끔 3) 300ms 뒤 저장 성공
- 기대 / 실제: 정보통신망법 제50조 제7항 · 시행령 제62조의3에 따라 수신 동의·거부·철회를 처리하면 **전송자 명칭, 의사를 표시한 날짜, 처리 결과**를 알려야 한다(보통 "2026.11.26 OSS 마케팅 정보 수신에 동의했어요" 같은 토스트/알럿). 실제로는 저장 성공 시 아무 안내 없이 스위치만 바뀐다. 서버 응답에도 날짜가 없다.
- 근거: `P/Features/Settings/NotificationSetting/NotificationSettingFeature.swift:197-200` (토글 → 저장만), `:263-275` (성공 응답에서 토스트 없음). `Data/Sources/Network/DTO/Response/NoticeSettingResponseDTO.swift:9-15` (날짜 필드 없음). 가입 때 '마케팅 정보 수신'(선택) 동의(`P/Features/TermsAgreement/TermsAgreementFeature.swift:63`)도 같은 안내가 필요할 수 있다(A5 범위).
- 고치는 방향: 마케팅 값이 바뀐 저장이 성공하면 날짜·전송자·결과를 담은 안내를 띄운다. 서버가 이메일·푸시로 따로 통지하는지 먼저 확인. 화면에서 바꾼 뒤 바로 나가 MY가 대신 저장하는 경로(A4-2)도 안내가 필요. · 분류: UI논의필요 + 웹/서버 확인필요
- 확신도: 중간 (서버가 별도로 통지한다면 앱 쪽은 필요 없음)

### A4-2 [P2] 알림을 바꾸고 바로 나가 MY가 대신 저장하다 실패하면, 실패 토스트가 설정 화면 밑에 가려져 보이지 않음
- 페르소나: P2 급한 손, P3 지하철
- 재현: 1) 불안정한 망에서 설정 › 알림 2) '마케팅 정보 알림'을 끔 3) 300ms 안에 (또는 요청이 도는 중에) 뒤로가기 → 설정 화면에 머묾 4) MY가 대신 보낸 저장이 실패
- 기대 / 실제: "알림 설정을 저장하지 못했어요" 안내가 보여야 한다. 실제로는 토스트가 MY 첫 화면(`MyProfileView`)의 overlay에 붙어 있어, 그 위에 push된 설정 화면에 가려 보이지 않는다(2초 뒤 사라짐). 사용자는 껐다고 믿지만 서버는 켜진 채 — 마케팅이면 철회가 반영 안 된 채로 남는다.
- 근거: `P/Features/MyProfile/MyProfileFeature.swift:906-919` (실패 시 MY의 `showToast`), `P/Features/MyProfile/MyProfileView.swift:177` (`.toastOverlay` — NavigationStack 루트 뷰에 붙음), `P/Features/AppTab/AppTabView.swift:116-128` (MyProfileView가 NavigationStack 루트, SettingsView는 destination). Toast는 `overlay(alignment: .bottom)` (`DesignSystem/Sources/Component/Toast/ToastView.swift:144-158`).
- 고치는 방향: 대신 저장 결과를 맨 위에 보이는 화면(설정)에 넘겨 그 화면 토스트로 띄우거나, 탭 전체 토스트(AppTab `showToast`)로 올린다. 기존 토스트 모양 그대로. · 분류: 코드수정-화면변화없음
- 확신도: 높음

### A4-3 [P2] 로그아웃을 누른 뒤 끝날 때까지 아무 표시가 없고, 그동안 다른 버튼(회원 탈퇴 등)이 눌림
- 페르소나: P3 지하철, P2 급한 손, P8 떠나는 사람
- 재현: 1) 느린 망에서 설정 › 로그아웃 › [로그아웃] 2) 알럿이 닫히고 설정 화면이 그대로 (서버 로그아웃 타임아웃 30초 + 카카오 로그아웃 + FCM 토큰 폐기) 3) 반응이 없어 다시 누르거나 '회원 탈퇴'를 누름
- 기대 / 실제: 탈퇴처럼 진행 중 덮개를 보이고 다른 조작을 막아야 한다. 실제로는 `isLoggingOut`이 어느 View에서도 쓰이지 않아 표시가 없다. 다시 [로그아웃]은 가드로 무시되어 더 헷갈리고, 그 사이 탈퇴를 확인하면 탈퇴 요청이 나간 뒤 로그아웃 완료가 MY 스택(설정)을 갈아엎어 탈퇴 응답이 버려질 수 있다(서버는 탈퇴, 앱은 "로그아웃했어요"만 보임).
- 근거: `P/Features/Settings/SettingsFeature.swift:264-267` (확인 → delegate만), `P/Features/AppTab/AppTabFeature.swift:533-555` (`isLoggingOut` 세팅 후 네트워크 정리), `:557-560` (`resetToGuest`로 MY 스택 교체), `Data/Sources/Network/Endpoint.swift:46-48` (기본 타임아웃 30초). `grep isLoggingOut *View.swift` → 없음.
- 고치는 방향: 로그아웃 중에는 설정에 탈퇴와 같은 덮개(`withdrawalGuard` 재사용)를 씌우거나 탭 전체 진행 표시. · 분류: UI논의필요
- 확신도: 중간 (표시 없음은 높음, 탈퇴 응답 유실 경합은 낮음)

### A4-4 [P2] 탈퇴 요청이 시간 초과로 실패했지만 서버는 처리한 경우, 다시 누르면 "이미 탈퇴" 안내만 뜨고 앱은 로그인 상태로 남음
- 페르소나: P3 지하철, P8 떠나는 사람
- 재현: 1) 느린 망에서 회원 탈퇴 확인 2) 서버는 탈퇴 처리했지만 응답이 30초를 넘겨 `timeout` → "서버 응답이 늦어요" 토스트, 로그인 상태 유지 3) 다시 탈퇴 → 서버가 U0004(이미 탈퇴 처리)로 답함
- 기대 / 실제: 탈퇴가 끝났다고 보고 게스트 전환 · 로컬 정리 · 탈퇴 안내를 해야 한다. 실제로는 U0004도 실패로 취급해 서버 문구 토스트만 띄우고 로그인 상태(토큰 · 최근 로그인 수단 · FCM 연결)를 그대로 둔다. 이후 앱을 다시 켜 자동 로그인되면 유예 중 재로그인으로 **탈퇴가 모르는 사이 취소**될 수 있다.
- 근거: `P/Features/Settings/SettingsFeature.swift:295-310` (실패는 모두 토스트만), `P/Error/DomainErrorMapper.swift:81-83` (U0004 → 서버 문구), `Data/Sources/Repositories/UserRepositoryImpl.swift:79-88` (`lastLoginProvider`는 성공 응답에서만 지움)
- 고치는 방향: 탈퇴 응답이 `.apiError(.alreadyWithdrawn)`이면 성공과 같게 `didWithdrawSuccessfully`로 보낸다. 서버가 재요청에 U0004를 주는지, 탈퇴 직후 토큰이 무효가 되는지(401 → 세션 만료 경로) 먼저 확인. · 분류: 웹/서버 확인필요 + 코드수정-화면변화없음
- 확신도: 낮음~중간 (서버 동작에 달림)

### A4-5 [P2] 알림 설정 조회 실패 토스트가 사라지면 스위치가 회색 자리표시로 영영 남고 다시 시도할 곳이 없음
- 페르소나: P3 지하철
- 재현: 1) 비행기 모드로 설정 › 알림 2) "알림 설정을 불러오지 못했어요 [다시 시도]" 토스트 3) 5초 기다리거나 쓸어 닫음 4) 망을 다시 켬
- 기대 / 실제: 다시 불러올 길이 있어야 한다. 실제로는 스위치 5개가 불러오는 중처럼 보이는 회색 캡슐로 남고, 망이 돌아와도 · 앱을 다녀와도(`sceneBecameActive`는 기기 권한만 다시 읽음) 그대로다. 뒤로 나갔다 다시 들어와야만 풀린다.
- 근거: `P/Features/Settings/NotificationSetting/NotificationSettingFeature.swift:251-261` (실패 시 토스트만), `:141-142` (복귀 시 기기 권한만), `:304-307` (재조회는 토스트 버튼뿐), `DesignSystem/Sources/Component/Toast/ToastState.swift:67-68` (버튼 토스트 5초)
- 고치는 방향: `sceneBecameActive`에서 `!isLoaded`면 서버 값도 다시 조회. 필요하면 자리표시 자리에 다시 시도 줄을 두는 건 논의. · 분류: 코드수정-화면변화없음 (복귀 재조회) / UI논의필요 (상시 재시도 버튼)
- 확신도: 높음

### A4-6 [P2] 설정 · 알림 화면의 뒤로 버튼에 VoiceOver 라벨이 없음
- 페르소나: P6 접근성
- 재현: 1) VoiceOver 켬 2) MY › 설정 (또는 설정 › 알림) 3) 왼쪽 위 뒤로 버튼에 초점
- 기대 / 실제: "뒤로, 버튼". 실제로는 이미지 이름("chevron-left" 비슷하게)으로 읽힌다. 같은 묶음의 이용 통계 화면은 `accessibilityLabel("뒤로")`가 있다.
- 근거: `P/Features/Settings/SettingsView.swift:163-172`, `P/Features/Settings/NotificationSetting/NotificationSettingView.swift:141-152` (라벨 없음) vs `P/Features/Settings/AnalyticsSetting/AnalyticsSettingView.swift:97`. 이미지 이름 `DesignSystem/Sources/Asset/Assets.swift:99` (`Common/Icon/chevron-left`). 앱 전체에서 `accessibilityLabel("뒤로")`는 1곳뿐이라 A7 전체 점검과 겹친다.
- 고치는 방향: 두 버튼에 `.accessibilityLabel("뒤로")`. · 분류: 코드수정-화면변화없음
- 확신도: 중간 (실기기 VoiceOver로 읽는 말 확인 필요)

### A4-7 [P2] 설정의 '마케팅 정보 수신 동의' 줄은 약관 문서만 열고, 실제 철회 스위치는 '알림' 화면의 '마케팅 정보 알림'에 있어 찾기 어려움
- 페르소나: P7 거절하는 사람, P8 떠나는 사람
- 재현: 1) 마케팅 수신을 끊으려고 설정 › 약관 및 정책 › '마케팅 정보 수신 동의' 2) 약관 웹 문서만 뜸 3) 끄는 곳을 못 찾음
- 기대 / 실제: 동의를 철회하는 길이 이름 그대로 이어져야 한다(동의만큼 쉬운 철회). 실제로는 문서 열람 전용이고, 끄는 스위치는 다른 묶음의 '알림 › 마케팅 정보 알림'(부제 "이벤트, 혜택 안내")이다. 또 가입 때 받은 마케팅 동의(`marketingAgreed`)와 알림 설정의 `marketingEnabled`가 서버에서 같은 값인지 앱 코드로는 알 수 없다 — 다르면 알림을 꺼도 이메일·문자 등 다른 경로의 광고 동의는 남는다.
- 근거: `P/Features/Settings/SettingsView.swift:68-70`, `P/Features/Settings/SettingsFeature.swift:206-210` (문서만 엶), `P/Features/Settings/NotificationSetting/NotificationSettingView.swift:83-92`

### A4-10 [P3] 알림 저장이 엇갈리면 화면 값과 서버 값이 어긋날 수 있음 (방금 끈 마케팅이 다시 켜지는 경우 포함)
- 페르소나: P3 지하철, P2 급한 손
- 재현 A: 1) 느린 망에서 '마케팅 정보 알림' 끔 → 뒤로(MY가 대신 저장 시작) 2) 곧바로 다시 설정 › 알림 3) 새 화면의 조회가 MY 저장보다 먼저 처리되어 '켜짐'으로 보임 4) 다른 스위치(예: 커뮤니티)를 바꿈 → 화면 전체 값(마케팅 켜짐 포함)을 보냄 → 늦게 처리되면 방금 끈 마케팅이 다시 켜짐

### A4-11 [P3] 탈퇴 직후 로컬 정리가 끝나기 전에 다시 로그인하면, 로그인한 뒤에 "탈퇴 신청이 끝났어요" 알럿이 뜨고 새 세션이 곧 폐기될 FCM 토큰을 등록할 수 있음
