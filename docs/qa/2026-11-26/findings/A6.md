## 점검한 흐름

- MY 빈 화면 → '내 스타일 등록하기' → 포지션 → 기술 → 서브미션 차례 등록 (register): **OK** — 단계마다 받은 프로필로 새 State를 만들고, 띠 · 특기 값도 이어받음. 단, 세 단계 모두 '없음'일 때 문구는 A6-9
- 등록 중간 '나중에 하기' / 뒤로 화살표: **문제** — 앞 단계는 이미 저장된 채 흐름 전체가 닫힘. 알림 없음 (A6-8)
- MY 펼친 카드 눌러 한 종류만 수정 (edit) → 완료 → 화면 닫고 "○○을 저장했어요": **OK**
- 아무것도 안 고른 상태로 진입 (큰 카드 '+ 선택하기'): **문제** — 눌러도 아무 일 없음 (A6-5)
- '없음' 고르기 → 완료: **확인 필요** — 키를 빼고 보내 서버가 안 지울 수 있음 (A6-1)
- 같은 카드 다시 누르기: 의도대로 선택 해제 → '없음' (MyStyleSettingFeature.swift:456 주석). 연타하면 고른 게 풀리는 문제는 A6-5에 함께 적음
- 고르는 도중 닫기 (뒤로 · 나중에 하기 · 스와이프): **OK** — `.cancel`이면 destination만 비우고 저장 안 함. 다시 열면 서버 값으로 새로 시작
- '완료' 연타: **OK** — 부모가 `isSaving=true`로 바꿔 버튼 · 뒤로 · 나중에 하기를 막음 (MyProfileFeature.swift:571)
- 저장 중 스와이프로 나감: **OK** — 응답이 오면 값만 반영하고 다음 단계 · 화면은 열지 않음. 다시 열기는 `isLoadingProfile`로 막고 "아직 처리 중이에요" 안내. (register 모드는 성공 토스트도 없이 조용히 저장됨. 사소해서 따로 적지 않음)
- 저장 실패: **OK** — 고르는 화면에 "저장하지 못했어요" 토스트가 뜨고 `isSaving`이 풀리며 고른 값은 남음(#156). MY의 `communityProfile`은 그대로라 **MY 카드는 바뀌지 않음**. 화면을 나가면 고른 값은 버려짐 (의도)
- 카드 바꾸기 애니메이션 중 연타: 상태(Reducer)는 OK. 겹친 카드의 방향은 실기기 확인 목록에 적음
- 등장 회전(뒷면 → 앞면) 중 다른 카드 탭 / 드래그: **OK** — `.task`가 취소되면 새 카드가 자기 등장을 다시 하고, 드래그를 시작하면 등장을 건너뜀 (FlippableStyleCard.swift:150, 174)
- 동작 줄이기: 등장 회전 · 조명 · 바꾸기 · MY 펼침 · 들썩임은 OK. **'카드 뒤집기' 읽어주기 동작과 드래그 뒤 회전은 그대로 3D로 돎** (A6-7)
- VoiceOver — MY 카드: **OK** (라벨 "최애 포지션, 가드 포지션", 힌트 "세 장을 펼쳐요 / 고르는 화면으로 가요")

- 띠 색별 앞면 글자 대비 (흰 · 파랑 · 보라 · 갈색 · 검정): **OK** — 계산해 봄. 제목 6.3~13:1, 설명 4.98(흰띠)~8.1:1로 모두 4.5:1 이상. 띠 미설정이면 흰띠 색 · 흰띠 캐릭터로 그림 (StyleCard.swift:24 주석, 의도). 그랄은 카드에 쓰이지 않음
- 아래 작은 카드 · 뒷면 글자 대비: **문제** (A6-10)
- 큰 글씨: **넘침 없음** — 앱 전체 글꼴이 `Font.custom(_, fixedSize:)` (DesignSystem/Sources/Typography/Font+.swift:54-93)라 크기가 그대로임. 큰 글씨를 키워도 카드 글자가 안 커지는 건 앱 전체 방침이라 A6 결함으로 적지 않음

- 서버가 모르는 기술 코드를 줄 때: **문제** — 크래시는 없지만 조용히 '안 고름'이 됨 (A6-2)
- 남의 프로필 카드 (읽기 전용, 누르면 다시 덮임): OK. 세 장 다 비었을 때 힌트는 A6-11

## 결함

### A6-1 [P1] '없음'으로 바꿔 저장하면 키가 빠진 요청이 나감 — 서버가 '안 보낸 값은 그대로 둠'이면 최애가 안 지워짐
- 페르소나: P1 처음이 · 일반 사용자
- 재현: 1) 최애 포지션을 '탑'으로 저장해 둠 2) MY → 펼친 '최애 포지션' 카드 → 아래 줄 '없음' 3) '포지션 설정 완료'
- 기대 / 실제: 기대는 최애 포지션이 지워지는 것. 실제 요청 JSON에는 `favoritePosition` 키가 아예 없음. 서버가 키가 없으면 기존 값을 두는 방식이면 응답에 'TOP'이 그대로 오고, "포지션을 저장했어요" 토스트 뒤에도 MY 카드가 '탑 포지션'으로 남음(앱은 응답 프로필을 그대로 씀, MyProfileFeature.swift:775-776)
- 근거:
  - Data/Sources/Network/DTO/Request/PostCommunityProfileRequestDTO.swift:50-55 — `self.favoritePosition = profile.favoritePosition?.rawValue` (Optional). 합성 Encodable이라 nil이면 `encodeIfPresent`로 키를 뺌. 같은 파일 120행 주석도 이렇게 적어 둠
  - Presentation/.../MyProfile/MyProfileFeature.swift:541 — 도장은 "nil 이면 요청 JSON 에서 키가 빠져 **BE 가 기존 값을 유지**하므로 "" 를 보낸다"
  - 반대로 MyStyleSettingFeature.swift:348-349는 "키가 빠지면 서버의 기존 특기가 **지워질 수 있어**"라고 적어 둠 → 섹션마다 서버 방식이 다른지 코드로는 알 수 없음
- 고치는 방향: POSITION · TECHNIQUE · SUBMISSION 저장에서 키를 빼면 지워지는지 서버에 확인. 안 지워지면 도장처럼 지움 값(`""` 또는 명시적 `null` 인코딩)을 보냄 · 분류: 웹/서버 확인필요
- 확신도: 낮음 (서버 방식에 따라 결함이 아닐 수 있음. 영향이 커서 P1로 둠)

### A6-2 [P2] 서버가 앱이 모르는 기술 코드를 주면 조용히 '안 고름'이 되고, 그 칸을 저장하면 서버 값을 덮어씀
- 페르소나: P8 떠나는 사람(다른 기기 · 웹에서 고친 뒤 앱으로 옴) · 앱 업데이트를 안 한 사용자
- 재현: 1) 웹(또는 새 버전)에서 앱 enum에 없는 값(예: `favoriteTechnique: "BACK_TAKES"`, `bestPosition: "HALF_GUARD"`)을 저장 2) 이 버전 앱으로 MY 진입 3) 기술 칸이 '지정해 주세요'로 보임. 세 칸 다 모르는 값이고 대회 기록도 없으면 '나의 주짓수를 보여 주세요' 빈 화면 4) 그 칸을 눌러 아무 카드나(또는 '없음') 고르고 완료
- 기대 / 실제: 기대는 최소한 '알 수 없는 기술' 같은 표시와 함께 숨긴 특기(best)를 지키는 것. 실제로는 디코딩 단계에서 nil이 되어 (a) 고른 적 없는 사람처럼 보이고 (b) 같은 섹션을 저장하면 받은 값(nil)을 다시 보내니 숨겨 둔 `best*`가 키 없이 나가 서버 값이 사라질 수 있음(#118에서 지키려던 값)
- 근거: Data/Sources/Network/DTO/Response/CommunityProfileResponseDTO.swift:51-56 (`favoriteTechnique.flatMap { TechniqueType(rawValue: $0) }`), CommunityPublicProfileResponseDTO.swift:38-40, MyStyleSettingFeature.swift:474-475 (받은 best를 그대로 다시 보냄), PostCommunityProfileRequestDTO.swift:50-55
- 고치는 방향: 웹이 앱보다 많은 코드를 쓸 계획이 있는지 먼저 확인. 있으면 원래 문자열을 들고 있다가 그 섹션에서 건드리지 않은 값은 그대로 다시 보냄 · 분류: 웹/서버 확인필요
- 확신도: 중간 (코드 경로는 확실. 지금 웹이 다른 코드를 쓰는지는 모름)

### A6-3 [P2] 고르는 화면 아래 줄 카드가 VoiceOver에서 버튼 · 선택 상태로 읽히지 않고 줄임말로 읽힘

- 확신도: 높음

### A6-4 [P2] 고르는 화면의 큰 카드 그림 · 로고 · 뒤로 버튼이 에셋 이름으로 읽힘. 앞면은 조각조각 읽힘
- 페르소나: P6 접근성

- 근거: DesignSystem/Sources/Asset/Assets.swift:342-345 (`init(asset:)` → `self.init(asset.name, bundle:)`), Components/StyleCard.swift:44, Components/StyleCardBack.swift:29, MyStyleSettingView.swift:267-283 (뒤로 버튼에 라벨 없음), MyProfileStyleComponents.swift:390 (장식 카드), FlippableStyleCard.swift:133 (`accessibilityAction`이 묶이지 않은 컨테이너에 붙음)

- 확신도: 중간 (이름이 라벨이 되는 건 SwiftUI 동작. 실제로 어떻게 읽히는지는 실기기 확인)

### A6-5 [P2] 큰 빈 카드 '+ 선택하기'는 눌러도 아무 일이 없고, '없음'을 일부러 골라도 '선택하기'라고 씀
- 페르소나: P1 처음이, P2 급한 손
- 재현: A) 1) 최애를 하나도 안 고른 상태로 MY → '내 스타일 등록하기' 2) 화면 가운데 큰 '+ 선택하기' 카드를 누름 → 아무 반응 없음. B) 1) '탑'이 골라진 상태에서 아래 '탑' 카드를 두 번 빠르게 누름 2) 고른 것이 풀려 큰 카드가 '+ 선택하기'로 바뀜 3) 그대로 '완료'를 누르면 '없음'으로 저장됨
- 기대 / 실제: 큰 카드가 '+ 선택하기'라며 누르라고 하는데 탭 동작이 비어 있음(막다른 길). 아래 줄을 써야 한다는 걸 알려 주지 않음. '없음'을 고른 상태에서도 같은 카드가 나와 "아무것도 안 골랐다"와 "없음을 골랐다"를 구분할 수 없음. 같은 카드를 다시 누르면 풀리는 동작(의도, MyStyleSettingFeature.swift:456)은 연타에 약함
- 근거: MyStyleSettingView.swift:195-202 (`onTap: { // 탭 동작 없음 }`), Components/EmptySelectionCard.swift:35-44, MyStyleSettingView.swift:231-241
- 고치는 방향: (a) 큰 빈 카드를 누르면 아래 줄 첫 카드를 고르거나 아래 줄을 강조함 (b) '없음'을 골랐을 때는 '없음' 문구 카드로 바꿈 (c) 고른 카드를 다시 눌러도 풀리지 않게 하고 '없음' 카드로만 해제. 화면 · 동작이 바뀌어 논의 필요 · 분류: UI논의필요
- 확신도: 높음 (동작 자체는 확실, 결함으로 볼지는 디자인 판단)

### A6-6 [P3] MY의 포개진 카드를 두 번 빠르게 누르면 펼쳐지자마자 고르는 화면으로 넘어감 (누른 것과 다른 종류일 수 있음)
- 페르소나: P2 급한 손
- 재현: 1) 최애가 하나 이상 있는 MY, 카드가 포개진 상태 2) 맨 위(서브미션) 카드를 빠르게 두 번 탭
- 기대 / 실제: 기대는 첫 탭에 펼쳐지고 두 번째 탭은 무시되는 것. 실제로는 첫 탭에 `isOpen = true`가 되어 `showsOpen`이 바로 true가 되고, 두 번째 탭은 펼친 배치 기준으로 그 자리에 있는 카드의 `onStyleCardTapped`를 부름. 맨 위 카드의 포갠 자리 x=1.84w는 펼친 배치에서 가운데(기술) 카드 범위(w+8 ~ 2w+8)라 **'최애 기술'** 화면이 열림
- 근거: Presentation/.../MyStyleSetting/MyProfileStyleComponents.swift:172-186 (펼치기와 이동을 같은 탭이 분기), 159-169 (포갠 자리 `pileCenterX [0.58, 1.21, 1.84]` vs 펼친 자리)
- 고치는 방향: 펼친 뒤 애니메이션 시간(~0.6초) 동안은 수정 이동을 무시함(예: 펼친 시각을 기억해 두고 확인) · 분류: 코드수정-화면변화없음
- 확신도: 중간 (애니메이션 중 탭이 어느 배치 기준으로 맞는지는 실기기 확인)

### A6-7 [P3] 동작 줄이기를 켜도 '카드 뒤집기'(VoiceOver 동작)와 드래그를 놓은 뒤 큰 카드가 3D 스프링으로 돎
